# SSM_FINAL_REBUILD_2026

Complete, reproducible research pipeline for a hybrid Ed25519 + ML-KEM-512
(post-quantum, FIPS 203) Adaptive Session Security Manager (SSM) for
wearable healthcare IoT authentication — real dataset, real crypto
benchmarks, real formal verification, and a paper generated from those
results, not typed by hand.

This is a **complete, independent rebuild**, not an edit of the old project
at `..\conf works\` (left untouched — see `paper/audit/OLD_PAPER_AUDIT.md`
for what auditing it found, and `OLD_VS_NEW_AUDIT.md` for the full
side-by-side numeric comparison and why an exact match with the old numbers
was never the goal).

## Status: pipeline complete

Every stage below has been run for real, on real data, at least once, and
its own test suite (where one exists) passes. See:

- `DECISION_REPORT_PHASE_2.md` — the evidence-based investigation behind the
  two frozen data-handling decisions (split sessions, S02 duplication).
- `SSM_ALGORITHM_DECISION.md` — the SSM threshold/scoring fix decided
  **before** any real experiment was run.
- `DERIVATION_REPORT.md` — traces every headline number: RAW DATA →
  PROCESSING → EVENT → SSM DECISION → AGGREGATION → TABLE/FIGURE → PAPER.
- `OLD_VS_NEW_AUDIT.md` — old paper vs. new pipeline, numbers and methodology.
- `FINAL_REPRODUCIBILITY_REPORT.md` — the final consistency/quality-gate audit.
- `formal_verification/README.md` — ProVerif results (single-session: all 8
  queries true; unbounded attempt: 7/8 true, 1 honestly reported as
  unresolved).

## Ground rules this project follows (do not violate these when extending it)

- No number appears in `paper/` unless it traces to one of: (A) the protocol
  specification, (B) the dataset's own documentation, (C) a benchmark this
  project's own code actually ran, (D) an experimental output this project's
  own code actually produced, or (E) a cited external source.
  `DERIVATION_REPORT.md` has the full trace for every headline figure.
- Thresholds, denominators, and aggregation methods are never adjusted to
  make a result look better. Where the new result differs from the old
  paper's (in either direction), the real new result is kept and reported.
- Every table and figure in `paper/` is generated by
  `src/analysis/generate_tables_figures.py` from files under `results/`,
  never typed in by hand.
- There is exactly ONE SSM engine (`src/ssm/ssm_engine.py`) and exactly ONE
  protocol implementation (`src/protocol/protocol.py`). Every experiment,
  the sanity trace, and the sensitivity sweep import these same two modules
  — nothing re-implements the decision logic or the handshake separately.
- If something cannot be reproduced or verified, it is reported as such
  (see `formal_verification/README.md`'s honest treatment of the unbounded
  ProVerif attempt), not silently worked around.

## Dataset

PhysioNet "Wearable Device Dataset from Induced Stress and Structured
Exercise Sessions" v1.0.0 (DOI 10.13026/zzf8-xv61). Downloaded, extracted,
and checksum-verified (708/708 files against the dataset's own official
`SHA256SUMS.txt`) — see `data/metadata/dataset_manifest.json` for the full
provenance record.

**`data/raw/` is not committed to Git.** The extracted dataset is roughly
several hundred MB of per-subject CSV files, and PhysioNet's Open Data
Commons license terms are most cleanly satisfied by redistributing the
official downloader/verifier rather than a bundled copy. To reproduce it
from scratch on any machine:

```bash
python src/preprocessing/download_dataset.py
```

This re-downloads the official archive, verifies every file's SHA-256
against PhysioNet's own checksums, and extracts it to `data/raw/extracted/`.
`data/raw/` and `data/processed/` should be listed in `.gitignore`;
`data/checksums/` and `data/metadata/` (which are small, text-only
provenance records, not the dataset itself) are committed.

## Two frozen scientific decisions (do not silently change these)

1. **Split sessions** (STRESS/f14, AEROBIC/S11, ANAEROBIC/S16 — each
   recorded across two Bluetooth-disconnected files): treated as ONE
   continuous session with the real measured gap preserved (91.3 s / 219.1 s
   / 51.4 s respectively), not concatenated as if no time passed, and not
   treated as two separate authentication contexts. See
   `DECISION_REPORT_PHASE_2.md` Decision 1 and `src/preprocessing/session_builder.py::SPLIT_SESSIONS`.
2. **S02/STRESS signal duplication**: truncated at the documented boundary
   (ACC 49542 rows, BVP 99088, EDA/TEMP 6192 each), discarding the
   duplicated second copy rather than the whole subject. HR/IBI ambiguity is
   disclosed as an unresolved limitation that does not block this project,
   since the SSM feature pipeline does not use HR/IBI. See
   `DECISION_REPORT_PHASE_2.md` Decision 2 and
   `src/preprocessing/session_builder.py::S02_TRUNCATION`.

## Reproducing everything

### Linux / macOS / cloud sandbox

```bash
pip install -r requirements-lock.txt --break-system-packages   # or a venv without the flag
python run_all.py                    # full run, downloads + verifies the dataset first
python run_all.py --skip-download    # if data/raw/ is already populated and verified
python run_all.py --tests-only       # just the two test suites (fast sanity check)
```

### Windows / VS Code

1. Install Python 3.11+ from python.org (check "Add to PATH" during install).
2. Open this folder in VS Code (`File > Open Folder...`).
3. Open a VS Code terminal (`` Ctrl+` ``) and run:
   ```bat
   pip install -r requirements-lock.txt
   run_all.bat
   ```
   or double-click `run_all.bat` in File Explorer.
4. To run just the tests (e.g. from VS Code's Testing panel, or the
   terminal): `run_all.bat --tests-only`.
5. Formal verification (`formal_verification/*.pv`) requires ProVerif
   (https://bblanche.gitlabpages.inria.fr/proverif/) installed separately
   and on `PATH`; it is not part of `run_all` because not every machine will
   have it installed. Run manually:
   ```bat
   cd formal_verification
   proverif -in pitype protocol_model.pv
   proverif -in pitype unbounded_attempt.pv
   ```

Pipeline order (identical in `run_all.py`/`run_all.bat`, DATA →
PREPROCESSING → SSM → CRYPTO → EXPERIMENT → RESULTS → TABLES/FIGURES →
TESTS gate before trusting results):

1. Download + verify raw dataset → `data/raw/`
2. Build sessions (frozen Decisions 1 & 2 applied) → sanity summary printed
3. Feature extraction → `data/processed/feature_table.csv`
4. SSM engine unit tests (16 boundary tests) — must pass
5. Protocol unit tests (7 tests) — must pass
6. Real crypto benchmark → `results/json/crypto_benchmark.json`
7. Real-dataset SSM experiment → `results/csv/`, `results/json/ssm_activity_summary.json`
8. 25-event sanity trace (reproducibility check, explicitly not a headline claim)
9. Sensitivity analysis (T_max / A_th / R_max sweeps) → `results/json/sensitivity_analysis.json`
10. Generate all tables/figures from `results/` only → `paper/tables/`, `paper/figures/`

## Known, disclosed limitations (not hidden)

- `failed_resumptions` is always 0 in the real-dataset experiment — the
  PhysioNet dataset has no real authentication-failure signal, so this term
  of the anomaly score is untested against real failure data. See
  `SSM_ALGORITHM_DECISION.md` §3.
- HR/IBI signal ambiguity for S02/STRESS is unresolved; irrelevant to this
  project's results because the feature pipeline uses only accelerometer
  magnitude, but stated here rather than silently ignored.
- The unbounded/replicated ProVerif model found 1 of 8 queries false,
  diagnosed as a likely modeling gap (not a confirmed protocol
  vulnerability) — see `formal_verification/README.md`. Not cited as
  verified in the paper.
- Compute-time-reduction percentages carry roughly ±0.5 percentage point
  run-to-run variance from real wall-clock crypto timing (bandwidth
  reduction is exact/deterministic). See `DERIVATION_REPORT.md` §4.
